# 03. 데이터 설명

`make seed` 는 항상 **똑같은 데이터**를 만듭니다 (무작위 값을 `RAND()` 대신 번호의 MD5 해시로 계산).
그래서 멘토님이나 다른 사람이 같은 SCALE 로 만들면 같은 id 에 같은 값이 들어 있고, 결과를 서로 비교할 수 있습니다.

## 테이블과 규모

| 테이블 | small | full | 주요 컬럼 |
|---|---|---|---|
| users | 10만 | 100만 | email, phone(문자열), status |
| sellers | 1천 | 1만 | |
| categories | 100 | 200 | |
| products | 20만 | 100만 | seller_id, category_id, price, status, created_at |
| posts | 10만 | 100만 | user_id, title, content(약 500바이트), status, like_count, created_at |
| likes | 약 94만 | 약 947만 | post_id, user_id, created_at |

처음엔 모든 테이블에 **PRIMARY KEY 만** 있고, 외래 키도 없습니다.

## 실험을 위해 일부러 넣은 특징

| 특징 | 내용 | 쓰이는 실험 |
|---|---|---|
| status 쏠림 | posts: PUBLISHED 90% / DRAFT 7% / DELETED 3% · products: ON_SALE 85% / SOLD_OUT 12% / HIDDEN 3% | E03, E05, E10 |
| 판매자 쏠림 | 번호가 작은 판매자일수록 상품이 많음 (대형 판매자) | E01, E06 |
| 인기글 쏠림 | 게시글의 1%가 좋아요 0~599개, 나머지는 0~20개 | E02, E12 |
| 같은 작성 시각 | posts.created_at 은 분 단위라서 같은 시각의 글이 자주 생김 | E08 (tie-breaker) |
| 문자열 전화번호 | users.phone = `'010'` + 8자리 (예: user 77777 → `'01000077777'`) | E09 |
| 제목 패턴 | `게시글 제목 {id} - {스프링/JPA/인덱스/MySQL/도커} 이야기` | E09 |
| 중복 없는 좋아요 | (post_id, user_id) 조합은 절대 겹치지 않음 → UNIQUE 인덱스 생성 가능 | E02, E12 |
| 흩어진 좋아요 | 같은 게시글의 좋아요가 테이블 곳곳에 흩어져 저장됨 (실제 서비스처럼) | E02 |

## 실험에 쓰기 좋은 값 (small · full 공통)

| 용도 | 값 | 특징 |
|---|---|---|
| 보통 판매자 | `sellerId=500` | 상품 수 small 131개 |
| 대형 판매자 | `sellerId=1` | 상품 수 small 6,321개 (전체의 약 3%) |
| 보통 게시글 | `postId=12342` | 좋아요 12개 |
| 인기 게시글 | `postId=21087` | 좋아요 599개 |
| 카테고리 | `categoryId=7` | |
| 날짜 | `day='2024-01-15'` | 하루에 약 1,440개 글 (1분에 1개꼴) |
| 회원 | `email='user77777@lab.dev'`, `phone='01000077777'` | |

## 데이터 직접 보기

```bash
make shell
```
```sql
SELECT * FROM posts LIMIT 3\G
SELECT status, COUNT(*) FROM posts GROUP BY status;
SELECT seller_id, COUNT(*) FROM products GROUP BY seller_id ORDER BY 2 DESC LIMIT 5;
SELECT post_id, COUNT(*) FROM likes GROUP BY post_id ORDER BY 2 DESC LIMIT 5;
```

> `seq` 테이블(1 ~ 1,000,000 숫자)은 데이터 생성과 E11 쓰기 실험에 쓰는 도우미 테이블입니다. 지우지 마세요.
